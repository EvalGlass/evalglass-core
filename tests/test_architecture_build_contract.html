Purpose

EGTS answers one critical question: can EvalGlass produce a green, passing, or non-failing result that a maintainer could misread as more authoritative than the evidence permits?

Critical rule: EGTS does not certify a host application. It certifies that EvalGlass keeps its own promises: effect-free core, one Verdict Engine, trace-native vendor-neutral input, typed evidence, honest authority, comparable baselines, host-owned truth, safe vendoring, and removable extension lanes.
Proof Type Meaning Required Result
Contract proof Public contracts exist and serialize as documented. TraceEnvelope, EvalUnit, EvidenceBundle, Scorecard, and verdict payloads are exercised by real product code.
Route proof Inputs travel through the intended route. Dataset, trace, subprocess, skill, judge, baseline, and optional-lane paths do not bypass their public ports.
Trust proof EvalGlass refuses unsupported claims. Informational, pass, fail, blocked, proposed, approved, calibrated, drifted, comparable, and non-comparable states are proven from typed artifacts.
Integration proof Adapters attach without changing meaning. OpenTelemetry/OpenInference conformance, backend adapters, ScoreSink, live judges, and richer units stay optional and deletable.

Non-Negotiables

Real Product Path

Required tests drive real EvalGlass public contracts. Test doubles are allowed only at effectful edges such as fake judge evidence and fixture host commands.

No Duplicate Verdict Engine

EGTS may declare an expected verdict and compare it to product output. It must not compute verdicts from authority, scores, thresholds, policy, or baselines.

Typed Artifacts First

Scorecard JSON and RunRecord JSON are primary. Markdown, terminal output, and CI annotations are rendering checks.

Hermetic Required Tier

Required tests run without network, credentials, live models, hosted trace backends, Docker, daemons, vector stores, or optional lanes.

Route Fidelity

A route test must use the route under proof. Trace tests cannot construct final examples directly. Skill tests cannot fake install output by copying files.

Negative Controls

Seeded-bad products, malformed artifacts, overclaiming reports, and broken fixtures prove that checkers fail for the right reason.

Proof Rings

The proof rings mirror the product rings but remain test-system concerns. They keep EGTS strict without turning it into a separate execution platform.

Proof Ring Owns Must Not Own
Contract Proof Schema snapshots, serialization, evaluator protocol fixtures, score-state fixtures, verdict-row fixtures. Product semantics or alternate aggregation.
Route Proof Dataset, trace, subprocess, judge, baseline, skill, and optional-lane scenario paths. Bypassing the route under proof.
Trust Proof Authority, data policy, threshold approval, judge calibration, baseline comparability, report overclaim checks. Human approval or domain truth.
Integration Proof OpenTelemetry/OpenInference conformance, backend adapters, ScoreSink, live judge lanes, richer EvalUnit lanes. Required-tier dependency on hosted services or provider SDKs.
Evidence Governance Coverage registry, proof planner, evidence reports, negative controls, deletion verification. Product verdicts, product authority, or broad workflow orchestration.

Components

Component Owns Must Not Own Primary Output
Scenario Catalog Declarative scenario files with target ticket, public contract, route, fixtures, expected artifact state, and coverage tags. Hidden expectations in checker code. Validated scenario definitions.
Coverage Registry Mapping from product tickets and architecture promises to required scenario IDs. Inferring product verdicts or authority. Coverage report and missing-obligation list.
Proof Planner Static selection of suites for a product ticket, milestone, changed contract, or optional lane. Ad hoc implementation control or weakening required obligations. Deterministic command plan and required evidence list.
Fixture Factory Datasets, traces, baselines, rubrics, calibration records, host repos, fake judge evidence, specimen programs, and adapter stubs. Constructing final core objects when a route is under test. Hermetic scenario workspace.
Scenario Runner Invoking real core runner, CLI, skill installer, or optional-lane command. Replacing normalization, aggregation, authority, verdict, or exit mapping. Command result and artifact paths.
Checker Engine Comparing declared expectations against typed product outputs. Calculating expected product verdicts. Check result with violated contract names.
Evidence Reporter Human-readable and machine-readable proof summaries. Treating evidence as product authority. Coverage, command, artifact, and blocker report.

Execution Flow

1. TargetTicket, milestone, public contract, product ring, or optional lane.
2. PlanCoverage registry selects required obligations and commands.
3. MaterializeFresh workspace and host-owned truth fixtures.
4. Run ProductReal core, CLI, skill, or lane command executes.
5. CollectRunRecord, Scorecard, reports, ledgers, diffs, exit class.
6. CheckDeclared expectations compared to typed product output.
7. Meta-TestNegative controls prove checkers are not shallow.
8. ReportEvidence, coverage gaps, blockers, and artifact paths.
  • A scenario cannot pass if expected verdict, exit class, authority claim, route, provenance, or artifact obligations are missing.
  • Product failures and test-system failures are separated in the evidence report.
  • Evidence reports are append-only for a run; retries create new run records.

Fixture And Isolation Contract

Fixture Family Proves Forbidden Shortcut
Core contract fixtures Contracts, evaluator protocol, score states, aggregation, authority, verdict rows. Runtime adapters or filesystem/network effects in core tests.
Dataset JSONL fixtures DatasetStore, references, dataset status, malformed records. Constructing final Example objects when dataset route behavior is under test.
Local trace JSONL fixtures TraceSource, trace provenance, malformed traces, data policy, call-level EvalUnit. Passing raw trace objects directly to evaluators.
Open-convention trace fixtures OpenTelemetry/OpenInference-shaped spans, messages, tool calls, timing, model metadata. Requiring a tracing backend SDK in required tests.
Specimen programs TaskRunner, subprocess JSON in/out, timeouts, stderr, malformed output. Calling host code in-process when subprocess replay is under test.
Baseline fixtures ComparableRunFingerprint, baseline promotion, changed dimensions, regression gate behavior. Comparing score numbers without provenance.
Skill fixture repos Discovery, vendoring, vendor-manifest.json, evalglass.lock, scaffolded host-owned truth. Treating copied files as proof that the skill flow ran.
Optional lane fixtures Trace backends, ScoreSink, live judges, annotation, synthetic data, richer units, deletion checks. Making optional SDKs required for local proof.

Checker Contract

Checker Reads Asserts Must Not
Contract checker Public modules and serialized examples. JSON compatibility, stable enums, required fields, invalid state rejection. Bless undocumented public drift.
Scorecard checker Scorecard JSON. Verdict, authority explanation, metric summaries, status counts, diagnostics, baseline state. Compute verdict from metric values.
Trace checker Trace artifacts and run artifacts. Raw trace -> TraceEnvelope -> EvalUnit -> Example route fidelity. Accept vendor-shaped evaluator-visible data.
Authority checker Scorecard authority fields. Proposed, approved, calibrated, drifted, policy, comparable, non-comparable claims. Approve data, thresholds, judges, or baselines.
Skill boundary checker File diffs, manifest, lock, scaffold output. Managed files and host-owned truth remain separated. Allow silent host-owned overwrite.
Optional lane checker Lane artifacts, dependency metadata, deletion results. Lane attaches through ports and can be removed. Allow optional lane code to change core meaning.
Checker rule: compare declared expectation to real product output. Never calculate the expected EvalGlass verdict from product internals.

Negative Controls And Meta-Tests

EGTS must prove that the tests themselves are capable of failing. A trust product with shallow tests is dangerous.

Negative Control Purpose Expected EGTS Behavior
Mutated verdict payload Proves checkers do not ignore verdict fields. Scorecard checker fails with violated VerdictPayload contract.
Missing authority reason Proves reports cannot pass without typed authority. Authority checker fails before report checker.
Blocked score encoded as zero Proves score status is not collapsed into value. Score checker and aggregation expectation fail.
Vendor trace leaked to evaluator Proves route normalization boundary. Trace checker fails with route-fidelity violation.
Skill overwrites host-owned rubric Proves vendoring boundary. Skill boundary checker fails with host-owned mutation.
ScoreSink mutates verdict Proves sink immutability. Optional lane checker and local Scorecard comparison fail.

Milestone Proof Suites

Suite Product Scope Proved Required Proof
EGTS-M0 Core Proof EG-M0 public contracts, evidence model, score model, diagnostics, registry, evaluator protocol, aggregation, provenance, authority, verdict matrix, serialization. Real core fixtures emit RunRecord, Scorecard, and verdict payloads for informational, pass, fail, blocked, score-state, validity, and baseline cases.
EGTS-M1 Runtime Proof EG-M1 CLI/config, local JSONL datasets, local JSONL traces, route convergence, evaluator loading, result persistence, reports. Dataset and trace scenarios converge into Example plus EvidenceBundle; reports render from Scorecard; default runs stay informational.
EGTS-M2 Trust Runtime Proof EG-M2 subprocess replay, comparable baselines, data policy, CI annotations, exit mapping, infrastructure error separation. CI behavior is derived only from real verdict payloads; non-comparable and policy-forbidden claims are honest.
EGTS-M3 Skill Proof EG-M3 discovery, install plan, vendoring, manifest, lock, scaffold, first-run checklist, re-vendoring. Fixture host repos install cleanly; runtime works after skill removal; scaffolded assets are informational.
EGTS-M4 Judge Proof EG-M4 JudgeModel, fake judge evidence, rubric provenance, calibration, threshold approval, drift, live lane boundary. Fake judge scenarios need no network; uncalibrated metrics remain informational; calibrated approved metrics gate only through the Verdict Engine.
EGTS-M5 Extension Proof EG-M5 optional extension framework, OpenTelemetry/OpenInference conformance, backend adapters, ScoreSink, richer EvalUnit, synthetic governance. Every extension attaches through ports, preserves typed contracts, and passes deletion verification.

Jira And Coverage Contract

The updated Jira workbook is product-only. EGTS does not add a second set of test epics to it. EGTS maintains a coverage map from product tickets to proof obligations.

Product Ticket Field EGTS Coverage Obligation
Owner componentSelects checker family and fixture route.
Public contractsMaps to contract snapshots, route scenarios, and artifact checks.
Acceptance criteriaBecomes declared scenario expectation or explicit manual-review note.
DependenciesDefines minimum proof order and prerequisite suites.
Product ringMaps to proof ring: contract, route, trust, integration, or evidence governance.
Optional lane labelRequires opt-in lane scenario plus deletion verification.

Coverage records include product ticket key, architecture source section, public contract, scenario IDs, fixture families, checker families, required command, negative-control obligation, and status.

EGTS is not done when tests exist. EGTS is done when it proves that real EvalGlass cannot quietly overclaim.
